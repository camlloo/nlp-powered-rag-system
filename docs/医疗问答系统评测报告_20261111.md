# 医疗问答系统评测报告（借鉴检索增强论文评测方法 · 第二次全量评测）

- **日期**：2026-11-11
- **被测系统**：NLP_RAG 检索增强医疗问答系统（FastAPI + pgvector 混合检索 + 证据约束生成 + 引用溯源）
- **方法参照**：王永刚硕士学位论文《基于检索增强与大模型的医疗问答方法研究》（北京印刷学院）

## 1. 摘要

| 维度 | 关键结果 |
|---|---|

| 检索（cMedQA 论坛库） | recall@1 0.166，recall@10 0.275，MRR@10 0.313（n=200，水位偏低；漏斗分析显示瓶颈在证据截断，见 §4.3） |

| 盲评胜出率（带参考答案重裁） | RAG 准确性 **70%**、完整性 **68%** 反超；专业性/安全性维度仍落后（见 §6.3） |

**一句话结论**：检索-证据链路质量高（小库内近乎全中），生成端忠于证据（context_recall=1.0），系统价值集中在**事实准确性**；短板在 cMedQA 类口语长尾检索、小库覆盖不足导致的"资料不足"式回答，以及证据忠实性约 22% 的失分（措辞性扩展）。

## 2. 对论文评测方法的借鉴与本系统的差异

### 2.1 采纳的四种做法

| 论文做法 | 论文出处 | 本次落点 |
|---|---|---|
| 0–5 五维裁判评分（含**专业性/安全性**医疗特需维度） | §5.6.3 表 5-3 | `qa` 轨：二元分 + `dim_means_0_5`（§5.1） |
| 多候选**盲评胜出率**（随机位次、允许平局） | §4.3 表 4-4~4-6 | 新增 `preference` 轨：RAG 全管线 vs 同底座裸模型（§6） |
| 性能效率指标（成功率 / 平均·最小·最大响应时间） | §5.6.4 表 5-2 | 各轨逐请求计时，`results/system_perf.json`（§8） |
| 余弦相似度（答案 vs 参考）等客观指标 | §3.3.2 | `qa` 轨 answer-gold 余弦（§5.1） |

### 2.2 不采纳 BERTScore 的理由

论文以 BERT-Score P/R/F1 为主客观指标，但医疗长答案场景下其**组间区分度差**（论文自身三数据集各组 F1 差距普遍 <0.02），且需引入 torch 推理栈。本报告用更可归因的组合替代：检索排序指标（P/R/F1@k、MRR）+ RAGAS 四指标 + 余弦相似度。

### 2.3 评测范式的三点不同（对齐论文时须知）

1. **基座强度**：论文对比 7B 本地模型 + LightRAG；本系统底座为百炼 qwen3.8-flash（通识强得多），"裸模型基线"本身就能答得漂亮，因此偏好实验更难，RAG 的增量价值主要显现在事实维度而非流畅度维度。
2. **知识规模**：论文图谱知识库规模大；本系统评测库仅 1,000 条百科答案 + 10,000 篇论坛帖子，"资料不足"类回答部分源于此。
3. **裁判模型**：论文用 DeepSeek-V3.2 评 Qwen 底座（跨家族）；本次裁判与生成同为 qwen3.8-flash（同族），存在自我风格偏好风险，已在 §9 局限中披露。

## 4. 检索效果（retrieve 轨）

判定口径：`/retrieval/debug` **最终证据集（evidence）** 文本与金标文档互相包含（去空白/标点）记命中；证据集为空记未命中。此口径衡量的是"真正送进生成器的检索质量"，@k 超过证据集长度后自然封顶。

### 4.1 指标表（n=200/源）

| 指标 | cMedQA 论坛库 | 华佗百科库 |
|---|---|---|
| Precision@1 / Recall@1 / F1@1 | 0.280 / 0.166 / 0.208 | 0.965 / 0.965 / 0.965 |
| Recall@3 / @5 / @10 | 0.209 / 0.259 / 0.275 | 0.965 / 0.965 / 0.965 |
| MRR@10 | 0.313 | 0.965 |
| 向量通道 Top1 余弦均值 | 0.749 | 0.892 |

> 注：cMedQA 检索轨首跑（13:5x）时该库快照仅含 30/40 分片——根因是跨知识库同名文件的对象替换语义把后补分片连带软删（见 §9.2-7）。索引修复后本报告数字为重跑值；其余轨道不受影响。

### 4.2 华佗百科库：近乎满分

recall@1=0.965 且 @1 到 @10 无差异——命中即排第一。验证了此前 BM25 标题词加权修复（标题路径词×2）的效果在本轮数据与索引下依然成立；未命中的 3.5% 为金标答案不在库内表述变体所致。

### 4.3 cMedQA 论坛库：低水位的漏斗归因（补充实验）

recall@10 仅 0.275。为定位原因，从 200 题判分结果中抽 60 条 miss，利用 `kb_chunk.title_path`（文档标题即金标 pid）逐层核查金标去向：

| 漏斗层级（candidates→evidence） | 金标已进入该层的比例 |
|---|---|
| lexical 词法通道（50） | 18%（11/60） |
| vector 向量通道（50） | 65%（39/60） |
| fused（99） | 68%（41/60） |
| **reranked（top-30）** | **75%（45/60）** |
| evidence（最终 ≤6 块） | 0%（若出现则判分不会是 miss，交叉验证判定口径） |
| 完全未进入任何候选 | 32%（19/60） |

三个结论：
1. **判定口径不是借口**：pid 级核查显示"文本互含判 miss"的误伤为 0——低召回是真实的检索-组装失败，此前"口径偏严"的猜测不成立（已修正）。
2. **最大瓶颈是证据块数硬上限**：75% 的 miss 金标其实已排在 rerank top-30 内，但生成端只收 `EVIDENCE_MAX_BLOCKS=6` 块（`app/retrieval/service.py:202`，与 top_k 取小），金标停在第 7–30 名进不了上下文。这同时解释了 @5/@10 曲线快速封顶（证据集实际平均 5.6 块）。
3. **词法通道贡献很低**（18%）：论坛口语问法与短答复文本几乎没有词面重叠，召回几乎全靠向量通道；剩余 32% 是真正的语义鸿沟（金标答复过短过泛，如"建议就医"类）。

据此的改进路径（按性价比）：放宽证据块数至 10–12 并同步扩 context 预算（直接解锁 ~75% miss 中进入证据的部分）；对口语查询加改写/扩展；扩充语料规模。

## 6. 对比偏好评测：RAG 全管线 vs 裸模型（preference 轨，n=50）

同一裁判、同一 50 题（与 qa 轨同子集），候选 A/B 随机位次、盲评五维+综合，统计"被判为更优的比例"。

### 6.1 无参考答案口径（严格论文口径，表 4-4~4-6 对应）

| 维度 | RAG 胜 | 裸模型胜 | 平 |
|---|---|---|---|
| 准确性 | 8% | 90% | 2% |
| 完整性 | 6% | 94% | 0% |
| 逻辑性 | 2% | 96% | 2% |
| 专业性 | 2% | 98% | 0% |
| 安全性 | 0% | 100% | 0% |
| 综合 | 2% | 98% | 0% |

**裸模型压倒性胜出**。人工复核样本确认这不是接线错误：无参考答案时，裁判按"常识印象"评判，裸模型（同为 qwen3.8-flash）的回答结构完整、面面俱到（平均长度 800+ 字，含"常见诱因/注意事项/请就医"套话），而 RAG 回答受证据约束（平均 566 字）、开头带"根据提供的资料"、遇小库覆盖不足时明示"资料不足"——在无参考口径下这些忠实性特征全部被当成"不完整"。

### 6.2 带参考答案重裁（同 50 组配对、同随机位次，裁判词加入参考答案与"不因长度/排版加分"）

| 维度 | RAG 胜 | 裸模型胜 | 平 |
|---|---|---|---|
| 准确性 | **70%** | 26% | 4% |
| 完整性 | **68%** | 26% | 6% |
| 逻辑性 | 6% | 46% | 48% |
| 专业性 | 18% | 80% | 2% |
| 安全性 | 22% | 72% | 6% |
| 综合 | 42% | 58% | 0% |

### 6.3 两口径对照的结论

- **事实维度**（准确/完整）：引入参考答案后，RAG 从 8%/6% 逆转到 **70%/68%**——检索增强的价值真实存在，但**在无参考盲评中不可见**（论文其底座为 7B 弱基线，RAG 增益在流畅度上即可显现；本系统底座通识太强，情形不同）。
- **风格维度**（专业/安全）：两口径下 RAG 都输。裸模型长于"教科书式分型 + 就医提醒"话术，裁判（同族模型）对这类表达稳定给出更高专业/安全分；RAG 回答引用标记密集、语气克制，吃亏。
- 综合维度带参考后 42% vs 58%，差距收窄但未反超——当前 1,000 条小库下，RAG 在"答得全、答得漂亮"层面仍不敌自由生成，其确定性优势在"答得对、不编造"。
- 方法论提示：论文式无参考胜出率指标对本系统组合（强底座+小库）**不具判别力且有风格偏置**，建议后续评测固定采用带参考重裁口径。

## 9. 结论与局限

### 9.1 结论

1. **检索-证据链路**：库内检索近乎满分（recall@1 0.965），context_recall 1.0，说明"找得对、找得全"；cMedQA 口语化论坛检索水位低（recall@10 0.275），漏斗归因显示主瓶颈是**证据块数硬上限 6**（75% miss 的金标已进 rerank top-30）而非排序本身（§4.3）。
2. **生成质量**：对照金标，二元正确分 0.94、五维 4.5–4.9 分；faithfulness 0.778 有约 22% 的措辞性扩展空间。
3. **RAG 的价值形态**：对强底座模型，RAG 的增量不在"答得流畅全面"而在"答得有据可查"——带参考口径下准确性胜出率 70%，无参考口径下反而 8%。评测必须双口径并披露。
4. **拒答策略**：忠实性守门在选择题型上代价明显（37% 题拒答放弃得分），建议对非诊疗型任务放宽。

### 9.2 局限

1. **同族裁判偏差**：生成与裁判同为 qwen3.8-flash，风格自偏好方向不可分离；论文用 DeepSeek 评 Qwen 可规避。后续建议引入跨族裁判（百炼 deepseek 系或本地模型）复核 preference/qa。
2. **盲评截断**：裁判输入两侧各截 1,500 字符，超长回答的尾部不可见（两侧同规则）。
3. **样本量**：qa/preference 50、ragas 20，均值±噪声带较宽；判定全部固定 seed=42 可复现，扩样直接加大 `--limit` 即可。
4. **知识库规模**：百科库仅 1,000 条（金标答案所在 test split），检索满分部分是"考自己复习范围"的结果，不代表生产规模表现；华佗数据噪声（§5.1）也放大了完整性失分。
5. **cMedQA 判定口径为文本互含**（与语义判分口径不可直接比较）；但 §4.3 的 pid 级交叉验证显示判定误伤为 0，低召回结论对口径不敏感。
6. **ragas 轨未记录时延**（该命令未接入计时汇总），工程指标表缺该行。
7. **过程事故披露（已修复）**：对象存储 key 以（日期, 用户, 文件名）为粒度，两个评测库的分片文件同名（part-000..009.md）且同日上传，共用 URI 的"同名替换"语义使后一批上传**跨库软删前一批库的文档**——华佗库一度发布 0 chunks 快照（全线拒答）、cmedqa 库缺 10 分片（检索轨首跑数字受损，已重建索引并重跑，本报告为修复后数字）。排查确认 reindex 的修订号防护本身正常，真正缺陷在上传入口的替换作用域未限库。**已修复**：跨库同名同 URI 上传现被 409 fail-closed 拒绝（同库替换语义保留），评测分片文件名也已加源前缀（cmedqa-part-*、huatuo-part-*）并通过端到端验证。
